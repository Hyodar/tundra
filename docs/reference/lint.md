# Lint reference

Generated from the `tundravm check` rule registry by `uv run python -m tundravm._reference docs/reference` (Python 3.12). Do not edit it by hand: `tests/docs/test_reference.py` fails when it is stale.

Every code an `Image` file can hit, and what to change in it. `tundravm check --explain CODE` prints one row. The severity is the default, then each other level a code reports at and when.

| Code | Severity | What it checks | How to fix |
|---|---|---|---|
| `cloud-glue-unconditional` | warning | A unit that only works on one cloud (a cloud agent's) has no ConditionVirtualization= for it, while the image's targets= also boot elsewhere, where it runs and fails. | Gate it on its cloud, so it stays inert elsewhere: Service(..., unit=DropIn(extra={"Unit": {"ConditionVirtualization": "ID"}})). |
| `component-conflict` | error | Two configurations of one component are included under one name (components=, a profile's add=), so their declarations and exports would mix. | Include one configuration of the component, or name the second one apart: a name= or id= field on it, or class Second(Component, name="..."). |
| `component-requires-missing` | error | A component holds an export (an Endpoint, a ServiceRef, a readiness) of a component the profile does not include. | Add the component that exports it to components= (or to the profile's add=), beside the one that holds it. |
| `debloat-removes-declared-file` | warning | A File is shipped under a directory the image empties at the end of the build (/var/log, /var/cache), so the file never reaches the image. | Ship the file outside the directory the message names; a service's logs= and state= directories are made at boot. |
| `debloat-removes-needed-unit` | warning | A Service is named like a systemd unit the image's debloat masks (systemd-*), or a shipped unit file depends on one, so it stops or never starts; or the image ships a tmpfiles.d file, which nothing applies: the debloat masks boot-time tmpfiles. | Rename the Service, or drop the dependency; tundravm decides which systemd units the debloat keeps, so report one the image needs. Ship a tmpfiles.d path itself: File(owner=), Tree(owner=), or a service's state= or runtime=. |
| `edit-missing` | error | A profile's changes= edit a value it does not inherit from the image or the profile it extends, so the edit changes nothing. | Edit only what the profile inherits (value.ref.edit(...) on a value the image or the extended profile declares); to declare the value in this profile, put it in add=. |
| `executable-stale` | error | A service's argv names a path a Build installed before the profile's changes= edited or removed that Build, so the image no longer has the file. | Point the argv at what the edited Build installs (its install= destination), or edit the service's argv in the same profile. |
| `export-stale` | error (warning when the profile only edits what the provider composed, which exports do not follow) | A component holds an export of a provider this profile configures differently: another configuration in add=, or changes= editing what the provider composed, which its exports do not follow. | Pass the consumer the export of the configuration this profile includes, or change the provider through its own fields instead of editing what it composed. |
| `file-path-duplicate` | error | One path is shipped twice with different content (a File and a Tree holding the same path, two components), and only the last one ends up in the image. | Keep one: drop the File, or leave the path out of the Tree with Tree(exclude=[...]); if two components write it, drop one or merge their content into one File. |
| `hardening-disabled` | warning | A Service runs without a sandbox (hardening=Hardening.none()). | Name the preset for its runtime (hardening="static", "jit", "node", "python" or "dotnet"), relax one knob of it (hardening=Hardening.preset("static", devices=[...], capabilities=[...])) or use hardening="relaxed", instead of dropping them all. |
| `hardening-relaxed` | info | A Service relaxes knobs of the strict sandbox (hardening="relaxed", or a preset's deviations), and each one widens what a compromised process can do. | Keep only the knobs the program needs; the message lists the relaxed ones. |
| `hook-covered` | info | A Mkosi(scripts=[...]) script runs a command a declaration already covers (useradd, groupadd, usermod, systemctl enable). | Declare what the message names (User(...), Group(...), Service(...)) instead of running the command. |
| `identity-collision` | error | One thing is declared twice with different values (a File at one path, a Service and Service.packaged() of one name, a User), so the image could keep only one of them. | Declare it once; a profile that needs another value edits the inherited one in changes= with value.ref.edit(...) instead of declaring it again in add=. |
| `instance-key-exposed` | error | A File, a unit=DropIn(...) or a shipped unit file names /run/tundravm/instance-key.pem, the private key the image generates at boot, which only the services that bind it may read, and only through their credentials. | Bind it: Service(credentials=[InstanceKey()]) (or InstanceKey() in argv or environment=) renders LoadCredential= and the ordering; the program reads $CREDENTIALS_DIRECTORY/instance-key. |
| `local-changed` | error | A Local source's directory changed since the lock: its content digest is not the one the lock pins, so a build refuses it. | Review the change, then run `tundravm lock` to record the new digest and commit the lockfile; a development build (`tundravm build --dev`) re-pins it itself. |
| `lock-added` | error | The image has a section the lock does not record (a new profile or source). | Review the change, then run `tundravm lock` to record it and commit the lockfile; `tundravm lock --check` shows the same drift without writing. |
| `lock-changed` | error | A section of the image or of one profile (or a source's ref) changed since the lock. | Review the change, then run `tundravm lock` to record it and commit the lockfile; `tundravm lock --check` shows the same drift without writing. |
| `lock-missing` | error | A production build has no lockfile to build against: a production build is a locked build, so its bytes reproduce and its manifest records every pin (a development build writes the lockfile first; `check` notes it). | Run `tundravm lock`, review and commit the lockfile, then build. |
| `lock-removed` | error | The lock records a section the image no longer has. | Review the change, then run `tundravm lock` to record it and commit the lockfile; `tundravm lock --check` shows the same drift without writing. |
| `lock-stale` | error | Every section matches the lock, but the image's digest does not. | Review the change, then run `tundravm lock` to record it and commit the lockfile; `tundravm lock --check` shows the same drift without writing. |
| `profile-empty` | info | A Profile declares nothing of its own (no add=, no changes=), so it builds the same image as the one it extends. | Declare what it adds in add= or changes=, or take it out of profiles=. |
| `relation-conflict` | error | A unit's relations contradict each other: it pulls in and conflicts with one unit (unit=DropIn(requires=[...], conflicts=[...])), is ordered both before and after one, or names itself. | Drop one of the relations. |
| `remove-missing` | error | A profile's changes= remove a value it does not inherit from the image or the profile it extends, so the removal does nothing. | Remove only what the profile inherits (value.ref.remove() on a value the image or the extended profile declares), or drop the removal from changes=. |
| `requires-without-after` | info | A shipped unit file Requires= another without After=, so both start in parallel. | Add After= for the same unit, so this one starts once it is up; a Service's requires=[other.ready] renders both. |
| `rule-undeclared` | error | A component reports a code its class does not declare, so --explain cannot say what it checks or how to fix it. | Declare the code on the component class: rules = (Rule(CODE, SEVERITY, SUMMARY, FIX),), with Rule from tundravm.components. |
| `secret-in-env` | error | A Service's environment= or argv (or a shipped unit file) holds what looks like a secret, baked into every copy of the image. | Deliver it at boot instead of baking it into the image: declare Secret(NAME) and pass it in the service's argv or environment=, where it renders as the path the service reads it at and binds it; `tundravm secrets deliver` sends it after attestation. |
| `secret-in-file` | error | A File ships what looks like a secret (a private key, a token), baked into every copy of the image and every registry that holds it. | Deliver it at boot instead of baking it into the image: declare Secret(NAME) and pass it in the service's argv or environment=, where it renders as the path the service reads it at and binds it; `tundravm secrets deliver` sends it after attestation. |
| `service-program-missing` | error | A Service's program (its argv's first element) is nothing the image ships: no File, Tree or Build installs it, and no listed package is known to. | Add the Debian package that ships it to packages=, or run a GoBinary, CargoBinary or Build as the argv's first element, or ship it with File.copy(Path(...), PATH, mode=0o755). |
| `service-runs-as-root` | info | A Service runs as root (user="root"), so a compromise owns the whole guest. | Drop user= to run as a system user named after the service (declared for you); grant one capability with hardening=Hardening.preset("static", capabilities=[...]) if it needs one. |
| `service-user-missing` | error | A Service(user=...) (or a shipped unit file's User=/Group=) names an account that nothing creates, so systemd refuses to start it. | Declare User(NAME) in users= (Group(NAME) in groups=) of the image or the same profile, or drop user= to run as the system user named after the service, which is declared for you. |
| `socket-service-started` | info | A service a shipped .socket file starts on demand is also enabled at boot. | Declare the socket on the service instead, Service(..., socket=Listen(...)), which enables the socket alone; a shipped unit file leaves [Install] out of the service. |
| `socket-service-unpaired` | error (warning when the profile installs packages, which may ship it) | A shipped .socket file activates a service the profile neither ships nor enables. | Ship the service next to the socket, or name the one it starts with Service=; a Service(socket=Listen(...)) renders both units. |
| `source-unpinned` | warning (error when the policy refuses moving refs, info when the policy allows them) | A source build, built kernel or downloaded package has no pin in the lockfile, so a moving ref builds different bytes. | Run `tundravm lock` to pin every source at once (`tundravm build` then fetches each on the host), or declare an immutable source: Git(url, ref) with a 40-hex commit ref, or Http(url, sha256=...). Locking names a dead upstream ref, with every other source it cannot resolve, before anything is written. |
| `state-dir-mkdir` | info | A unit=DropIn(exec_start_pre=...) (or a shipped unit file's ExecStartPre=) creates a state directory that systemd can create and own for the service user. | Pass state=NAME, logs=NAME or runtime=NAME on the Service; a shipped unit file uses StateDirectory=, LogsDirectory=, RuntimeDirectory= or CacheDirectory=. |
| `timer-service-enabled` | warning | A service a shipped .timer file starts is also enabled at boot, so it runs off schedule. | Declare the schedule on the service instead, Service(..., timer=Every("1h")) or Calendar(...), which enables the timer alone; a shipped unit file leaves [Install] out of the service. |
| `timer-unit-missing` | error (warning when the profile installs packages, which may ship it) | A shipped .timer file activates a unit the profile neither ships nor enables. | Ship the unit next to the timer, or name the one it starts with Unit=; a Service(timer=Every("1h")) renders both units. |
| `tool-missing` | error (warning when the tool is optional) | A host tool the build backend needs is missing. | Install the tool the message names; `tundravm doctor` lists what this host can do. |
| `toolchain-drift` | warning | The running toolchain (mkosi, the tools tree, tundravm, the measurement tools) differs from the one the lock records, so a build may differ. | Run the locked tools, or `tundravm lock --update toolchain` to record this toolchain instead. |
| `tree-drift` | error | A file of the committed mkosi tree differs from what the image compiles to. | Rewrite the tree with `tundravm build --tree-only DIR`, review the diff and commit it. |
| `unit-as-file` | info | A unit file is shipped as a File under a systemd unit directory, so tundravm neither renders, orders nor sandboxes it. | Declare it as a Service(NAME, argv, ...) in services=; its timer= and socket= render those units, and Service.packaged(NAME) runs a package's own. |
| `unit-collision` | error | Two services write one unit file (Service("app", argv) and Service("app", argv, timer=...)), so one silently replaces the other. | Give each its own name; what a service's unit says changes through its keywords and unit=DropIn(...), never through a second Service. |
| `unit-directive-unknown` | warning | A shipped unit file sets a directive systemd 257 does not know, which systemd ignores. | Check the spelling against systemd.directives(7); X- keys are left alone. A Service(...) keyword or unit=DropIn(...) is checked for you. |
| `unit-enable-noop` | warning | A unit the image enables (Service.packaged(NAME)) is shipped by a File without an [Install] section, so systemctl enable does nothing. | Add [Install] WantedBy=multi-user.target to the shipped unit text, or declare it as a Service(NAME, argv) instead of shipping its file. |
| `unit-exec-relative` | warning | A unit command (ExecStart= and the other Exec directives, unit=DropIn(exec_start_pre=) included) names its program by a relative name, and systemd's search path is not $PATH. | Spell the absolute path (/usr/bin/NAME or /usr/sbin/NAME). |
| `unit-extra` | info | A Service's unit=DropIn(...) (or a shipped unit file) sets what a Service keyword covers, which nothing then types or validates. | Use the keyword the finding names (resources=, shutdown=, environment=, ...); keep unit=DropIn(...) for what no keyword covers. |
| `unit-section-invalid` | error | A shipped unit file (a File under a systemd unit directory) has a section its unit type does not allow, which systemd ignores. | Move its directives to [Unit], [Install] or the unit type's own section; a Service(...) in services= renders a unit with the right sections. |
| `unit-value-invalid` | error | A shipped unit file gives a directive a value it does not accept, so systemd keeps the default. | Use a value the directive accepts; the message names what is wrong with it. A Service(...) keyword is checked for you. |
| `unit-written-at-runtime` | error | A service's argv (cp, tee, install, ln, a shell redirection) or a shipped tmpfiles.d line writes a unit under /etc/systemd/system, /run/systemd/system or /usr/lib/systemd/system at boot, so the attested image does not pin what runs. | Declare the unit as a Service(...) in services=; a value it needs at boot comes from a Secret(NAME) in credentials=, never from writing the unit. |
| `user-group-undefined` | error | A User(groups=[...]) names a group that nothing creates, so useradd fails during the build. | Add Group(NAME) to groups= of the image or the same profile, or drop it from the User's groups=. |
| `volume-tpm-on-cloud` | info | A Volume(unlock=TpmSeal(...)) seals its key to a cloud's vTPM (Azure's paravisor, Google's hypervisor), so the platform, not an attested release, decides who opens it; today's key-gen binds no PCR. | Unlock it with OperatorKey() (an operator sends the key after attesting the instance) or BrokerKey(url, audience=...) (a key broker does); keep TpmSeal(...) when that platform's vTPM is a boundary you accept. |

## Internal model

These codes check what only the internal model declares: an `Image` file cannot write it, and tundravm's own lowering keeps it clean. One reported for an image file is a bug: report it with the file. `--explain` marks them `internal`.

| Code | Severity | What it checks | How to fix |
|---|---|---|---|
| `debloat-removes-modules` | error | The debloat removes /usr/lib/modules while the kernel loads its drivers (virtio, tdx_guest, cloud NICs) from there, so they never load. | tundravm sets this itself (whether the debloat keeps the kernel's modules); report it. |
| `disk-device-guessed` | error (warning under Policy(storage_safety='warn')) | A disk that is formatted names no device, and automatic selection can pick the boot disk and format it. | tundravm sets this itself (each volume's device); report it. |
| `disk-device-unstable` | warning | A disk is formatted through a kernel name (/dev/sdb), which follows probe order and can point at another disk on the next boot. | tundravm sets this itself (each volume's device); report it. |
| `disk-key-path-mismatch` | warning | A disk reads its key from a path other than the one its key is written to, so the unlock finds no key. | tundravm sets this itself (where a volume's key is written); report it. |
| `disk-key-undefined` | error | A volume is encrypted with a key the profile does not declare, so it cannot be unlocked at boot. | tundravm sets this itself (a volume's key); report it. |
| `edit-invalid` | error | A profile's edit sets a field to a value the declaration refuses. | Fix the field values in the profile's changes=; the message carries the declaration's own error. |
| `external-delivery-unwired` | warning | Nothing in the image can tell when the secret delivery has written the secrets, so services start without them. | tundravm sets this itself (the secret delivery); report it. |
| `file-path-relative` | error | A file path contains '..' and may escape the image root. | Write the normalized absolute path instead. |
| `hook-after-undefined` | error | A build hook runs after a hook the profile does not declare. | tundravm sets this itself (the build hooks and their order); report it. |
| `hook-order` | error | A build hook is ordered after a hook of a later phase, which only runs after it. | tundravm sets this itself (the build hooks and their order); report it. |
| `image-arch-unsupported` | error | An aarch64 image uses what only boots x86-64: the amd64 EFI stub or the qemu target. TDX guests are x86-64. | tundravm sets this itself (the architecture); report it. |
| `kernel-missing` | error | A bootable image installs no kernel, so mkosi cannot build its UKI. | tundravm sets this itself (the kernel package); report it. |
| `kernel-modules-ignored` | warning | Kernel modules are selected, but the built kernel has no loadable modules, so the selection does nothing. | tundravm sets this itself (a built kernel's modules); report it. |
| `key-pipe-outside-run` | info | A key reads its pipe outside /run, where a FIFO survives reboots and can be replaced by a regular file. | tundravm sets this itself (where a volume's key pipe is); report it. |
| `mkosi-configure-script` | error | An mkosi setting adds ConfigureScripts, which rewrite the configuration after `mkosi summary` resolved it, so the summary would not describe the build. | Drop it: set what the script would set through the Image keywords or Mkosi(settings=). |
| `mkosi-environment-passthrough` | error | An mkosi setting passes the host's environment into the build, so the build depends on the machine it runs on. | Drop it from Mkosi(settings=): the build sees no host variable. |
| `needs-undefined` | error | A unit waits for a boot step or boot task the profile does not declare, so it would wait forever. | tundravm sets this itself (what a unit waits for: a service's requires=); report it. |
| `needs-without-init` | warning | A unit waits for runtime-init, but the profile declares no runtime-init step, so it waits for nothing. | tundravm sets this itself (what a unit waits for: a service's requires=); report it. |
| `network-missing` | warning | The profile serves ports or syncs time but brings up no network interface. | tundravm sets this itself (the network: every image implies Network()); report it. |
| `port-unreachable` | warning | A service listens on a port the firewall drops, so nothing outside reaches it. | tundravm sets this itself (the ports the firewall opens: each service's expose=); report it. |
| `secret-env-service-unknown` | error | A secret is delivered into the environment of a service the profile neither generates, ships nor enables. | tundravm sets this itself (which service a secret is delivered to); report it. |
| `secret-store-undefined` | error (warning when the compiled profile, not its declarations, lacks the disk) | The secrets are stored on a disk the profile does not declare. | tundravm sets this itself (where the secrets are stored); report it. |
| `secret-target-unsupported` | error | A secret goes to a target its delivery does not write at boot, so it never arrives. | tundravm sets this itself (where each secret is delivered); report it. |
| `setting-raw` | info | An mkosi setting sets a key tundravm already sets itself. | Drop it from Mkosi(settings=); it is for keys tundravm does not set. |
| `step-cycle` | error | The boot steps' after= and before= form a cycle, so runtime-init has no order to run them in. | tundravm sets this itself (the boot steps and their order); report it. |
| `step-undefined` | error | A boot step orders itself after or before a step the profile does not declare. | tundravm sets this itself (the boot steps and their order); report it. |
| `target-inconsistent` | error | A profile targets outputs that drop the cloud platform integration it inherits, so its UKI carries glue for a cloud it never boots on. | tundravm sets this itself (each profile's targets); report it. |
| `unit-raw` | info | A service is hand-written unit text instead of a typed Service. | Declare Service(NAME, argv, ...): the compiler renders the unit, its ordering after requires= and its enablement. |

## Shipped components

The codes each component of `tundravm.components` reports, as its class declares them (`rules`). A project's own components declare theirs the same way and are not listed here: `tundravm check IMAGE --explain CODE` prints one.

| Component | Code | Severity | What it checks | How to fix |
|---|---|---|---|---|
| `DevAccess` | `dev-access-rsa-key` | info | A development profile accepts an RSA SSH key where every current client makes ed25519. | Make an ed25519 key (ssh-keygen -t ed25519) and pass its .pub instead. |
| `Firewall` | `egress-unfiltered` | warning | A production profile accepts every outbound packet (no Egress, or one allowing 0.0.0.0/0 or ::/0), so a compromised service sends what it holds anywhere. | List what its services talk to: network=Network(egress=Egress(ports=[TCP(443)], hosts=[...])); what the baseline sends (NTS time, resolvers, cloud metadata) is accepted for you. A Profile(production=False) is exempt. |
| `Firewall` | `firewall-ssh-open` | warning | The firewall opens port 22 by hand, outside the SSH access that accepts only a key. | Drop 22 from Firewall(allow=) and use SshAccess(...) or dev=DevAccess(...), which open it only with a key to accept. |
| `Network` | `network-no-route` | warning | A static address without a gateway reaches its own subnet only, so NTS time and every remote endpoint fail. | Give it a gateway: Network(static=StaticAddress("10.0.0.5/24", gateway="10.0.0.1")). |
| `Observability` | `observability-plaintext` | warning | An Observability sink is http://, so the host and every hop read what the guest logs. | Point the sink at an https:// URL. |
| `Observability` | `observability-sink-unset` | warning | A production profile ships the journal to the in-guest receiver, so no log leaves the VM. | Pass JournalExport(url=) your systemd-journal-remote receiver's https:// URL. |
| `SshAccess` | `ssh-keys-baked` | warning | SSH keys are baked into a cloud image, so every instance of it lets their holders in as root. | Use SshAccess(from_delivery=True) so the control plane delivers the key at boot, or keep baked keys in a non-production profile with dev=DevAccess(...). |
| `Tdxs` | `tdxs-validator-unchecked` | warning | Tdxs validates peers' quotes with no expected measurements, so it accepts any genuine TD whatever it runs. | Pass Tdxs(expected_measurements=...), or build it with Tdxs.from_policy(POLICY). |
| `TeeBase` | `tee-base-clock` | warning | TeeBase(time=False) leaves the guest on the host's clock, so the host decides certificate expiry and attestation freshness. | Keep TeeBase(time=True), the default: authenticated NTS time. |
