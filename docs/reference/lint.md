# Lint reference

Generated from the `tundravm check` rule registry by `uv run python -m tundravm._reference docs/reference` (Python 3.12). Do not edit it by hand: `tests/docs/test_reference.py` fails when it is stale.

Every code tundravm itself reports. `tundravm check --explain CODE` prints one row. The severity is the default, then each other level a code reports at and when.

| Code | Severity | What it checks | How to fix |
|---|---|---|---|
| `cloud-glue-unconditional` | warning | A unit that only works on one cloud has no ConditionVirtualization= for it, while the profile's UKI also boots elsewhere, where it runs and fails. | Gate it on its cloud, so it stays inert elsewhere: Service(..., unit=DropIn(extra={"Unit": {"ConditionVirtualization": "ID"}})). |
| `component-conflict` | error | Two different component configurations share one name, so their declarations and exports would mix. | Use one configuration of the component, or give the second one its own name. |
| `component-requires-missing` | error | A component needs another component that the profile does not include. | Add the required component to components= (or to the profile's add=). |
| `debloat-removes-declared-file` | warning | The debloat deletes a path at finalize, after a declared file was placed there, so the file never reaches the image. | Ship the file outside the path the debloat removes (the message names it). |
| `debloat-removes-modules` | error | The debloat removes /usr/lib/modules while the kernel loads its drivers (virtio, tdx_guest, cloud NICs) from there, so they never load. | tundravm sets this itself (whether the debloat keeps the kernel's modules); report it. |
| `debloat-removes-needed-unit` | warning | The systemd debloat masks a unit a service is, or depends on, so the service stops or never starts. | Drop the dependency, or rename a Service called systemd-*; tundravm decides which systemd units the debloat keeps, so report one the image needs. |
| `disk-device-guessed` | error (warning under Policy(storage_safety='warn')) | A disk that is formatted names no device, and automatic selection can pick the boot disk and format it. | tundravm sets this itself (each volume's device); report it. |
| `disk-device-unstable` | warning | A disk is formatted through a kernel name (/dev/sdb), which follows probe order and can point at another disk on the next boot. | tundravm sets this itself (each volume's device); report it. |
| `disk-key-path-mismatch` | warning | A disk reads its key from a path other than the one its key is written to, so the unlock finds no key. | tundravm sets this itself (where a volume's key is written); report it. |
| `disk-key-undefined` | error | A volume is encrypted with a key the profile does not declare, so it cannot be unlocked at boot. | tundravm sets this itself (a volume's key); report it. |
| `edit-invalid` | error | A profile's edit sets a field to a value the declaration refuses. | Fix the field values in the profile's changes=; the message carries the declaration's own error. |
| `edit-missing` | error | A profile edits a declaration it does not inherit, so the edit changes nothing. | Edit only what the profile inherits from the profile it extends (or the image), or declare the value in its add= instead. |
| `executable-stale` | error | A service runs a path a Build installed before a profile edited or removed it, so the command names a file the image no longer has. | Point the service's command at what the edited Build installs, or edit the command in the same profile. |
| `export-stale` | error (warning when the profile only edits what the provider composed, which exports do not follow) | A component holds an export of a provider that this profile configures differently. | Pass the consumer the export of the component this profile includes, or change the provider through its own arguments instead of editing what it composed. |
| `external-delivery-unwired` | warning | Nothing in the image can tell when the secret delivery has written the secrets, so services start without them. | tundravm sets this itself (the secret delivery); report it. |
| `file-path-duplicate` | error | One path is declared several times with different content, and only the last one ends up in the image. | Keep a single declaration; if two components write the path, drop one or merge their content into one File. |
| `file-path-relative` | error | A file path contains '..' and may escape the image root. | Write the normalized absolute path instead. |
| `hardening-disabled` | warning | A unit runs without a sandbox (Hardening.none()). | Pick the preset for its runtime (hardening="NAME"), relax one knob of it (Hardening.preset("static", devices=(...), capabilities=(...))) or use hardening="relaxed", instead of dropping them all. |
| `hardening-relaxed` | info | A unit relaxes knobs of the strict sandbox, and each one widens what a compromised process can do. | Keep the knobs the program does not need; the message lists the relaxed ones. |
| `hook-after-undefined` | error | A build hook runs after a hook the profile does not declare. | tundravm sets this itself (the build hooks and their order); report it. |
| `hook-covered` | info | A build hook or boot step runs a command a declaration already covers (useradd, systemctl enable, mkdir and chown). | Declare what the message names instead of the command. |
| `hook-order` | error | A build hook is ordered after a hook of a later phase, which only runs after it. | tundravm sets this itself (the build hooks and their order); report it. |
| `identity-collision` | error | Two declarations with one identity (a path, a unit, an account) hold different values, so the image could only keep one of them. | Declare it once. To change an inherited declaration in a profile, edit it in the profile's changes= instead of declaring it again. |
| `image-arch-unsupported` | error | An aarch64 image uses what only boots x86-64: the amd64 EFI stub or the qemu target. TDX guests are x86-64. | tundravm sets this itself (the architecture); report it. |
| `kernel-missing` | error | A bootable image installs no kernel, so mkosi cannot build its UKI. | tundravm sets this itself (the kernel package); report it. |
| `kernel-modules-ignored` | warning | Kernel modules are selected, but the built kernel has no loadable modules, so the selection does nothing. | tundravm sets this itself (a built kernel's modules); report it. |
| `key-pipe-outside-run` | info | A key reads its pipe outside /run, where a FIFO survives reboots and can be replaced by a regular file. | tundravm sets this itself (where a volume's key pipe is); report it. |
| `local-changed` | error | A Local source's directory changed since the lock: its content digest is not the one the lock pins, so a build refuses it. | Review the change, then run `tundravm lock` to record the new digest and commit the lockfile; a development build (`tundravm build --dev`) re-pins it itself. |
| `lock-added` | error | The image has a section the lock does not record (a new profile or source). | Review the change, then run `tundravm lock` to record it and commit the lockfile; `tundravm lock --check` shows the same drift without writing. |
| `lock-changed` | error | A section of the image or of one profile (or a source's ref) changed since the lock. | Review the change, then run `tundravm lock` to record it and commit the lockfile; `tundravm lock --check` shows the same drift without writing. |
| `lock-missing` | error | A production build has no lockfile to build against: a production build is a locked build, so its bytes reproduce and its manifest records every pin (a development build writes the lockfile first; `check` notes it). | Run `tundravm lock`, review and commit the lockfile, then build. |
| `lock-removed` | error | The lock records a section the image no longer has. | Review the change, then run `tundravm lock` to record it and commit the lockfile; `tundravm lock --check` shows the same drift without writing. |
| `lock-stale` | error | Every section matches the lock, but the image's digest does not. | Review the change, then run `tundravm lock` to record it and commit the lockfile; `tundravm lock --check` shows the same drift without writing. |
| `mkosi-configure-script` | error | An mkosi setting adds ConfigureScripts, which rewrite the configuration after `mkosi summary` resolved it, so the summary would not describe the build. | Drop it: set what the script would set through the Image keywords or Mkosi(settings=). |
| `mkosi-environment-passthrough` | error | An mkosi setting passes the host's environment into the build, so the build depends on the machine it runs on. | Drop it from Mkosi(settings=): the build sees no host variable. |
| `needs-undefined` | error | A unit waits for a boot step or boot task the profile does not declare, so it would wait forever. | Declare what it requires in the same profile, or drop it from requires=. |
| `needs-without-init` | warning | A unit waits for runtime-init, but the profile declares no runtime-init step, so it waits for nothing. | Declare what the unit requires in the same profile, or drop it from requires= so it starts without waiting. |
| `network-missing` | warning | The profile serves ports or syncs time but brings up no network interface. | Add network=Network() to the Image, or ship a .network file. |
| `port-unreachable` | warning | A service listens on a port the firewall drops, so nothing outside reaches it. | Open it with the service's expose=[TCP(PORT)], or Firewall(allow=[TCP(PORT)]) for a program no Service runs. |
| `profile-empty` | info | A profile declares nothing of its own, so it builds the same image as the one it extends. | Declare what it adds in its add= or changes=, or remove it. |
| `relation-conflict` | error | A unit's relations contradict each other: it pulls in and conflicts with a unit, is ordered both before and after one, or names itself. | Drop one of the relations. |
| `remove-missing` | error | A profile removes a declaration it does not inherit, so the removal does nothing. | Remove only what the profile inherits from the profile it extends (or the image), or drop the removal from its changes=. |
| `requires-without-after` | info | A unit Requires= another without After=, so both start in parallel. | Add After= for the same unit, so this one starts once it is up. |
| `rule-undeclared` | error | A component reports a code its class does not declare, so --explain cannot say what it checks or how to fix it. | Declare the code on the component class: rules = (Rule(CODE, SEVERITY, SUMMARY, FIX),), with Rule from tundravm.components. |
| `secret-env-service-unknown` | error | A secret is delivered into the environment of a service the profile neither generates, ships nor enables. | tundravm sets this itself (which service a secret is delivered to); report it. |
| `secret-in-env` | error | A unit's environment or command line holds what looks like a secret, baked into every copy of the image. | Deliver it at boot: declare a Secret and pass it in the service's argv or environment=, where it is the path the service reads it at and binds itself. |
| `secret-in-file` | error | A shipped file holds what looks like a secret, baked into every copy of the image and every registry that holds it. | Deliver it at boot: declare a Secret and pass it in the service's argv or environment=, where it is the path the service reads it at and binds itself. |
| `secret-store-undefined` | error (warning when the compiled profile, not its declarations, lacks the disk) | The secrets are stored on a disk the profile does not declare. | tundravm sets this itself (where the secrets are stored); report it. |
| `secret-target-unsupported` | error | A secret goes to a target its delivery does not write at boot, so it never arrives. | tundravm sets this itself (where each secret is delivered); report it. |
| `service-program-missing` | error | A service's program (its argv's first element) is nothing the image ships: no declared file, tree or build installs it, and no listed package is known to. | Add the Debian package that ships it to packages=, or run a GoBinary, CargoBinary or Build as the argv's first element, or ship it with File.copy(Path(...), PATH, mode=0o755). |
| `service-runs-as-root` | info | A service runs as root, so a compromise owns the whole guest. | Drop user= to run as a system user named after the unit (declared for you); grant one capability with Hardening.preset("static", capabilities=(...)) if it needs one. |
| `service-user-missing` | error | A service (or a unit's User=/Group=) runs as an account that nothing creates, so systemd refuses to start it. | Declare the User or Group in the same profile, or drop user= to run as a system user named after the service. |
| `setting-raw` | info | An mkosi setting sets a key tundravm already sets itself. | Drop it from Mkosi(settings=); it is for keys tundravm does not set. |
| `socket-service-started` | info | A service a socket starts on demand is also enabled at boot. | Leave it out of [Install] and do not enable it; enable the socket alone. |
| `socket-service-unpaired` | error (warning when the profile installs packages, which may ship it) | A socket activates a service the profile neither ships nor enables. | Ship the service next to the socket, or name the one it starts with Service=. |
| `source-unpinned` | warning (error when the policy refuses moving refs, info when the policy allows them) | A source build, built kernel or downloaded package has no pin in the lockfile, so a moving ref builds different bytes. | Run `tundravm lock` to pin every source at once (`tundravm build` then fetches each on the host), or declare an immutable source: Git(url, ref) with a 40-hex commit ref, or Http(url, sha256=...). Locking names a dead upstream ref, with every other source it cannot resolve, before anything is written. |
| `state-dir-mkdir` | info | ExecStartPre= creates a state directory that systemd can create and own for the service user. | Use StateDirectory=, LogsDirectory=, RuntimeDirectory= or CacheDirectory= instead. |
| `step-cycle` | error | The boot steps' after= and before= form a cycle, so runtime-init has no order to run them in. | tundravm sets this itself (the boot steps and their order); report it. |
| `step-undefined` | error | A boot step orders itself after or before a step the profile does not declare. | tundravm sets this itself (the boot steps and their order); report it. |
| `target-inconsistent` | error | A profile targets outputs that drop the cloud platform integration it inherits, so its UKI carries glue for a cloud it never boots on. | tundravm sets this itself (each profile's targets); report it. |
| `timer-service-enabled` | warning | A service a timer starts is also enabled at boot, so it runs off schedule. | Leave it out of [Install] and do not enable it; enable the timer alone. |
| `timer-unit-missing` | error (warning when the profile installs packages, which may ship it) | A timer activates a unit the profile neither ships nor enables. | Ship the unit next to the timer, or name the one it starts with Unit=. |
| `tool-missing` | error (warning when the tool is optional) | A host tool the build backend needs is missing. | Install the tool the message names; `tundravm doctor` lists what this host can do. |
| `toolchain-drift` | warning | The running toolchain (mkosi, the tools tree, tundravm, the measurement tools) differs from the one the lock records, so a build may differ. | Run the locked tools, or `tundravm lock --update toolchain` to record this toolchain instead. |
| `tree-drift` | error | A file of the committed mkosi tree differs from what the image compiles to. | Rewrite the tree with `tundravm build --tree-only DIR`, review the diff and commit it. |
| `unit-as-file` | info | A unit file is shipped as a File, so tundravm neither renders, orders nor lints it. | Declare it as a Service(...); its timer= and socket= render those units. |
| `unit-collision` | error | Two declarations write the same unit file, so one would silently replace the other. | Rename one of them. A Service's own unit changes through its fields and unit=DropIn(...). |
| `unit-directive-unknown` | warning | A unit sets a directive systemd 257 does not know, which systemd ignores. | Check the spelling against systemd.directives(7); X- keys are left alone. |
| `unit-enable-noop` | warning | A unit is enabled but has no [Install] section, so systemctl enable does nothing. | Add [Install] WantedBy=, or stop enabling it. |
| `unit-exec-relative` | warning | A unit command (ExecStart= and the other Exec directives) names its program by a relative name, and systemd's search path is not $PATH. | Spell the absolute path (/usr/bin/NAME or /usr/sbin/NAME). |
| `unit-extra` | info | A service's unit=DropIn(...), or raw unit directives, set what a Service keyword covers, which nothing then types or validates. | Use the keyword the finding names (resources=, shutdown=, environment=, ...); keep unit=DropIn(...) for what no keyword covers. |
| `unit-raw` | info | A service is hand-written unit text instead of a typed Service. | Declare Service(NAME, argv, ...): the compiler renders the unit, its ordering after requires= and its enablement. |
| `unit-section-invalid` | error | A unit has a section its type does not allow, which systemd ignores. | Move its directives to [Unit], [Install] or the unit type's own section. |
| `unit-value-invalid` | error | A unit gives a directive a value it does not accept, so systemd keeps the default. | Use a value the directive accepts; the message names what is wrong with it. |
| `unit-written-at-runtime` | error | A service, boot task or boot step writes a unit under /etc/systemd/system, /run/systemd/system or /usr/lib/systemd/system at boot (cp, tee, install, ln, a shell redirection, a tmpfiles.d line), so the attested image does not pin what runs. | Declare the unit in the image as a Service(...); a value it needs at boot comes from a Secret through credentials=. |
| `user-group-undefined` | error | A user joins a group that nothing creates, so useradd fails during the build. | Declare the Group in the same profile, or drop it from the user's groups=. |
| `volume-tpm-on-cloud` | info | A volume's key is sealed to a cloud's vTPM (Azure's paravisor, Google's hypervisor), so the platform, not an attested release, decides who opens it; today's key-gen binds no PCR. | Unlock it with OperatorKey() (an operator sends the key after attesting the instance) or BrokerKey(url, audience=...) (a key broker does); keep TpmSeal when that platform's vTPM is a boundary you accept. |

## Shipped components

The codes each component of `tundravm.components` reports, as its class declares them (`rules`). A project's own components declare theirs the same way and are not listed here: `tundravm check IMAGE --explain CODE` prints one.

| Component | Code | Severity | What it checks | How to fix |
|---|---|---|---|---|
| `DevAccess` | `dev-access-rsa-key` | info | A development profile accepts an RSA SSH key where every current client makes ed25519. | Make an ed25519 key (ssh-keygen -t ed25519) and pass its .pub instead. |
| `Firewall` | `egress-unfiltered` | warning | A production profile accepts every outbound packet (no Egress, or one allowing 0.0.0.0/0 or ::/0), so a compromised service sends what it holds anywhere. | List what its services talk to: network=Network(egress=Egress(ports=[TCP(443)], hosts=[...])); what the baseline sends (NTS time, resolvers, cloud metadata) is accepted for you. A Profile(production=False) is exempt. |
| `Firewall` | `firewall-ssh-open` | warning | The firewall opens port 22 by hand, outside the SSH access that accepts only a key. | Drop 22 from Firewall(allow=) and use SshAccess(...) or dev=DevAccess(...), which open it only with a key to accept. |
| `Nethermind` | `nethermind-volatile-state` | warning | Nethermind keeps its database on the volatile root, so it resyncs from genesis at every boot. | Pass state=volume.directory('nethermind') on a Volume. |
| `Network` | `network-no-route` | warning | A static address without a gateway reaches its own subnet only, so NTS time and every remote endpoint fail. | Give it a gateway: Network(static=StaticAddress("10.0.0.5/24", gateway="10.0.0.1")). |
| `Observability` | `observability-plaintext` | warning | An Observability sink is http://, so the host and every hop read what the guest logs. | Point the sink at an https:// URL. |
| `Raiko` | `raiko-listens-publicly` | warning | Raiko listens beyond the loopback, so requests reach the prover without going through its AttestedTLS ingress. | Keep Raiko(listen='127.0.0.1:PORT'), the default, and reach it through the ingress. |
| `SshAccess` | `ssh-keys-baked` | warning | SSH keys are baked into a cloud image, so every instance of it lets their holders in as root. | Use SshAccess(from_delivery=True) so the control plane delivers the key at boot, or keep baked keys in a non-production profile with dev=DevAccess(...). |
| `Tdxs` | `tdxs-validator-unchecked` | warning | Tdxs validates peers' quotes with no expected measurements, so it accepts any genuine TD whatever it runs. | Pass Tdxs(expected_measurements=...), or build it with Tdxs.from_policy(POLICY). |
| `TeeBase` | `tee-base-clock` | warning | TeeBase(time=False) leaves the guest on the host's clock, so the host decides certificate expiry and attestation freshness. | Keep TeeBase(time=True), the default: authenticated NTS time. |
