# A login's commands: argparse-like params, a templated argv, a generated CLI

Date: 2026-11-08. Status: design; the Go runtime and the Python side are built against it
in parallel. Franco: "I think we should try and follow a similar syntax as argparse for
params and use a templating syntax for the command. Something like
`Command(params=[CommandParam("count", type=int, min=0, max=100)], runs=["/usr/bin/counter",
"{{count}}"], sudo=True)`. Then we should generate the Go CLI based on that. `type=` can be a
custom class which defines how to generate the validation."

On master a command is an argv template with typed holes (`Int`, `Choice`) the client fills
by position, one generic binary (`login-menu`) interprets `/etc/tundravm/logins/<name>.json`
at run time, and nothing prints help. Here the declaration reads like an argparse parser,
the argv is a template over the params, and tundravm writes a Go program per login into the
tree, which the image build compiles. There is no menu file and no interpreter.

## The spelling

The flashbox menu, as `examples/flashbox/image.py` writes it:

```python
ssh = SshAccess(
    login=Login(
        "searcher",
        owner=True,
        help="operate the flashbox searcher",
        commands={
            "status": firewall.commands.status,
            "toggle": firewall.commands.switch,
            "logs": Command(
                params=[
                    CommandParam("--lines", type=int, min=1, max=10000, default=200, help="lines from the end"),
                    CommandParam("--follow", type=bool, help="keep printing as the file grows"),
                ],
                runs=["/usr/bin/tail", "--lines", "{{lines}}", "{{#follow}}-f{{/follow}}", searcher.logs],
                help="the searcher's delayed output",
            ),
            "reboot": Command(runs=["/usr/bin/systemctl", "reboot"], sudo=True, help="reboot the VM"),
            "shell": Command(runs=["/usr/bin/bash"], dev=True, help="a shell as searcher"),
        },
    )
)
```

- `Login(commands={name: Command(...)})` stays a dict: the typed name on the left, as the
  subparser's name in argparse. `help=` on the login is the program's description.
- `Command(params=[...], runs=[...], *, sudo=False, modes=(), dev=False, help=None)`.
  `runs` is required and its first word is the program's absolute path. `sudo`, `modes` and
  `dev` mean what they mean today (`login-commands-2026-11-08.md`).
- `CommandParam(name, type=str, *, choices=None, min=None, max=None, default=None, help=None)`
  is `add_argument`. A name without dashes is positional: required, typed in declaration
  order. `--name` is an option: typed as `--name VALUE` or `--name=VALUE` anywhere after the
  command's name, and it needs `default=` unless its type is `bool`. In `runs` and in the
  help a param goes by its name without the dashes (argparse's `dest`).
- `type=int` needs `min=` and `max=`: what a login may pass is bounded. `type=str` needs
  `choices=`: there are no free strings. `type=bool` is a flag, options only, no `default`.
  `type=` an instance of a `ParamType` subclass brings its own validation (below).
- `runs` words are literals, paths (`directory / "file"`) or templates: `{{name}}` anywhere
  in a word is the param's value (`"--lines={{lines}}"` is one word); a word wrapped in
  `{{#flag}}...{{/flag}}` exists when the flag is given and is dropped otherwise. A word is
  never split, and nothing passes through a shell. Every param appears in `runs`, and every
  `{{name}}` names a param; both are refusals (`login-param-unused`, `login-param-unknown`).
- `firewall.commands.status` is `Command(runs=[MODE_SWITCH, "status"], sudo=True, help="the
  firewall mode in force")`; `firewall.commands.switch` is
  `Command(params=[CommandParam("mode", choices=[*modes])], runs=[MODE_SWITCH, "to", "{{mode}}"],
  sudo=True, help="switch the firewall mode")`.
- `--help`, `-h` and `help` are the program's; a command or param may not take them.

## Param types

A type says how a value is checked in the generated program, what sudoers admits, and how
the help spells its domain. The built-ins are private classes `type=` picks; a recipe may
pass its own instance:

```python
class ParamType:
    def usage(self) -> str: ...     # the domain in the help: "1-10000", "production|maintenance"
    def check(self) -> str: ...     # a Go expression over the string `value` yielding error
    def pattern(self) -> str: ...   # the anchored sudoers regex admitting what check admits
```

- `int` with bounds: `check` is `cli.Int(value, 1, 10000)`, `pattern` is `^[0-9]+$` (sudo
  admits the shape, the program enforces the bounds, as today).
- `str` with choices: `check` is `cli.OneOf(value, "production", "maintenance")`; the
  sudoers lines enumerate the values instead of a pattern (`pattern` returns `None`).
- `bool`: no value, no pattern; the flag's words are literals the sudoers lines enumerate
  with and without.
- A custom type is the test of the protocol: `tests/fixtures/native-tree/fixture.py` carries
  `Hex(64)` (`cli.Match(value, "^[0-9a-f]{64}$")`, the same regex as its pattern). The
  expression is compiled into that login's program, so it may use `cli.*` and the standard
  library only, and a `pattern` looser than its `check` is the author's bug, said in the
  manual.

## What it lowers to

- `payload/tundravm-cli/<login>/main.go`, the program; `dev.go` (`//go:build dev`) holding
  the `dev=True` commands, which only a development profile's build compiles (`-tags dev`,
  from `$PROFILES`); `cli.go`, the runtime copied verbatim from `tools/pkg/cli/cli.go`; a
  `go.mod` with no dependencies (`module <login>`, the toolchain's `go` line). Self-contained,
  pinned by the tree, built by the same Go step that builds `mode-switch`, installed as
  `/usr/libexec/tundravm/cli/<login>` (0755).
- The login's sshd block says `ForceCommand /usr/libexec/tundravm/cli/<login>`.
- `/etc/sudoers.d/<login>` is still rendered in Python: every argv a `sudo=True` command can
  produce (each flag given or not, one line per choice value, a param's `pattern` where it
  has one), at most 64 lines per command (`login-sudo-lines`: fewer flags or choices).
- Gone: `login-menu`, `tools/pkg/menu`, `/etc/tundravm/logins/`, `Int`, `Choice`.

## The generated program (the contract both sides build against)

`main.go` for flashbox, as the Python side writes it and `tools/pkg/cli` accepts it:

```go
// Code generated by tundravm from image.py; do not edit.
package main

var program = Program{
	Login: "searcher",
	Help:  "operate the flashbox searcher",
	Commands: []Command{
		{
			Name: "logs", Help: "the searcher's delayed output",
			Params: []Param{
				{Name: "lines", Option: "--lines", Usage: "1-10000", Default: "200", Help: "lines from the end",
					Check: func(value string) error { return Int(value, 1, 10000) }},
				{Name: "follow", Option: "--follow", Flag: true, Help: "keep printing as the file grows"},
			},
			Run: func(v Values) []string {
				return Words("/usr/bin/tail", "--lines", v.Get("lines"), v.If("follow", "-f"), "/persistent/data/delayed/output.log")
			},
		},
		{Name: "reboot", Help: "reboot the VM", Sudo: true,
			Run: func(v Values) []string { return Words("/usr/bin/systemctl", "reboot") }},
		{Name: "status", Help: "the firewall mode in force", Sudo: true,
			Run: func(v Values) []string { return Words("/usr/bin/mode-switch", "status") }},
		{Name: "toggle", Help: "switch the firewall mode", Sudo: true,
			Params: []Param{{Name: "mode", Usage: "production|maintenance",
				Check: func(value string) error { return OneOf(value, "production", "maintenance") }}},
			Run: func(v Values) []string { return Words("/usr/bin/mode-switch", "to", v.Get("mode")) }},
	},
}

func main() { Main(program) }
```

`dev.go`:

```go
//go:build dev

package main

func init() {
	program.Commands = append(program.Commands, Command{
		Name: "shell", Help: "a shell as searcher",
		Run: func(v Values) []string { return Words("/usr/bin/bash") },
	})
}
```

The runtime (`cli.go`, package `main`) defines `Program`, `Command` (`Name`, `Help`, `Sudo`,
`Modes []string`, `Params`, `Run`), `Param` (`Name`, `Option`, `Flag`, `Usage`, `Default`,
`Help`, `Check func(string) error`), `Values` (`Get`, `If`), `Words`, `Int`, `OneOf`,
`Match`, and `Main`. `Words` drops empty words, which is how `v.If` removes a flag's word.
Commands are sorted by name in the listing; templates with a `{{name}}` inside a word
become string concatenation in `Run`.

`Main` behaves as `login-menu` does today, plus help:

- The empty request prints the listing: `searcher: operate the flashbox searcher`, then
  `ssh searcher@HOST COMMAND`, then one line per command, `logs [--lines N] [--follow]`
  padded, its help, and `as root` or `maintenance only` where they apply.
- `--help`, `-h` or `help` prints the listing; `logs --help` prints the command's usage, each
  param with its domain, default and help, and `runs: /usr/bin/tail --lines <lines> [-f]
  /persistent/data/delayed/output.log` (`as root` when sudo).
- A refused request prints `what` and `fix: ...` on stderr as today and exits 2; a command
  outside the mode in force exits 1 with today's message. Unknown words, a missing
  positional, a value its `Check` refuses, an option given twice, a flag with a value: all
  refused with the command's usage as the fix. `--` is not accepted.
- The mode in force is read from `/run/tundravm/firewall-events` only when the command names
  modes. The environment is today's `menu.Environment`. A `Sudo` command execs `sudo -n`
  followed by its argv; the argv is never joined into a shell string.

## What `show` prints

The `Logins` section prints, per login, the listing the program prints and, per command,
the `runs:` line with `<name>` for each param and `[word]` for each flag's word, plus the
profiles a `dev=True` command exists in. `show --json` carries `logins` with `help`, `params`
(`name`, `option`, `type`, `usage`, `default`, `help`), `runs` (the template as written),
`sudo`, `modes`, `profiles`.

## Rejected

- Names in `runs` as objects (`runs=[..., lines, ...]`): Franco asked for a template; the
  string template reads as the argv the client sees in `runs:`.
- `Argument` and `Cli` as separate declarations: `CommandParam` under `Command` under the
  login's dict is argparse's shape already (parser, subparser, argument).
- A generic binary reading the declaration at run time: that is master; the program is now
  the declaration, readable in the tree and compiled, and a dev command is not compiled into
  production rather than hidden there.
- A shell script instead of Go: parsing a client's words in sh in front of `sudo` is the
  footgun this design exists to avoid.
- `nargs`, repeated options, free strings, nested subcommands: not here.
