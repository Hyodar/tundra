# Changelog

`## Unreleased` holds the next release's notes, one grouped note under `###` sections.
`scripts/release.py cut X.Y.Z` renames it `## X.Y.Z - <date>` and opens an empty one; the
`vX.Y.Z` tag's release body is that section, and a tag without one is refused
([docs/release.md](docs/release.md)).

## Unreleased

tundravm v2 makes mkosi accessible for confidential VMs by making the choices: Debian
trixie, systemd, a measured UKI, Intel TDX. You declare one Python `Image`, the compiler
writes one plain mkosi 27.1 tree, and thirteen commands take it to a locked, reproducible,
signed build that runs, deploys and attests. No compatibility alias is kept. The attested
endpoint has run simulated under QEMU only; no real TDX quote is recorded yet.

### SDK

- **Breaking:** `Image`, `Service`, `Component` and `Profile` replace `Recipe`, `Variant` and `Fragment`.
- **Breaking:** every public name has one home (`tundravm`, `.ports`, `.systemd`, `.components`, `.storage`, `.secrets`, `.sources`, `.errors`, `.testing`); flat imports are gone.
- **Breaking:** `profile` replaces `variant` everywhere, `--json` and `tundravm.testing` included; `show --json` says `image`, `components` and `profiles`.
- **Breaking:** the API speaks the public model (`Resolved.targets`, `.components`, `.production`, `class X(Component, name=)`, `ImageFile.component`); the internal-model test helpers and fixtures are gone.
- **Breaking:** `Image(volumes=, secrets=)` are gone: the image collects each volume and secret from what binds it.
- **Breaking:** `tundravm.bake` is `tundravm.build`, the command's verb, without an alias; its directory keyword is `into=` (was `build=`).
- `Component` is a dataclass with `compose()`, typed exports and an optional `check()`; `Profile(extends=, add=, changes=, production=)` edits with `value.ref.edit(...)` and `.remove()`.
- **Breaking:** a profile edit sets any `Service` keyword but `name=` (`readiness=`, `credentials=`, `unit=`, `timer=` and `quotes=` included) and builds what it implies, its probe, credential waits, drop-in, timer and firewall rule and its dependents' ordering; `service.ref.remove()` drops everything the service lowers to; a credential bound through argv or `environment=`, another built binary, another `user=` for a directory on a volume, dropping a readiness another service requires, removing a service another one requires and a `requires=` on the `.ready` of a service the image does not declare are refused.
- `Image` implies the TEE baseline, a curated kernel, a firewall that opens only exposed ports (and 8745 where the attested endpoint listens), one hardened user per service, and `tdxs`; the shipped library is `TeeBase`, `Network`, `Firewall`, `Tdxs`, `SshAccess`, `DevAccess`, `Observability` and `Container`.
- `Service` takes an argv; `expose=` alone opens a port; `requires=` waits for real readiness (`Notify`, `TcpProbe`, `HttpProbe`, `service.endpoint(port)` or a component's `self.service(name).endpoint(port)`, or `setup.output(path)`, which skips the service when its setup task wrote nothing); `hardening="python"` names the sandbox per runtime (`static`, `jit`, `node`, `python`, `dotnet`, `relaxed`), `Hardening.preset(NAME, ...)` a deviation; `quotes=True` joins the `tdx` group and requires the evidence service.
- An `Endpoint` of another service in a service's argv or `environment=` (which now takes one, rendered as its URL) implies `requires=` on that service's readiness, so `[signer, "-upstream", nethermind.rpc]` waits for Nethermind without saying it twice; a `requires=` naming the same service already says it, an upstream without a readiness adds no wait, a profile that removes the upstream is refused, and lint's `requires-implied` (info) names each wait it added.
- `TcpProbe` and `HttpProbe` read `interval=` as a systemd time span (`"500ms"` by default), as `timeout=` and `Every()` do; a span systemd does not read, zero or `infinity` is refused at construction.
- `HttpProbe(url)` refuses a URL that names no host (`"http://"`), which constructed and polled nothing.
- `Service.packaged(unit, package=, hardening=)` runs a Debian package's unit under the image's sandbox, which replaces the package's own; `convert --from systemd` writes it for drop-ins whose unit is not in the set.
- `Hardening(capabilities=["CAP_SYS_TIME"])` also drops `ProtectClock=` and allows `@clock` back, so a time daemon's grant takes effect; the boot probe's `service:` failure names a denied capability when the unit's status shows one.
- A list wherever a public value's docs show one type-checks: `Build(command=, packages=, install=)`, `User(groups=)`, `DropIn`'s lists, `Hardening(devices=, capabilities=, syscalls=)`, `GoBinary(tags=)` and `CargoBinary(features=)` take a `Sequence` and keep a tuple.
- Every image generates a fresh secp256k1 instance key at boot (tmpfs, root-only); `InstanceKey()` (`tundravm.secrets`) hands it to a service as a credential, `instance-key-exposed` refuses anything else naming it, and `run status` and `attest` print its public key while `show` says who takes it.
- `Generated(name)` (`tundravm.secrets`) is a secret the image writes at boot for the services that bind it, such as the Engine API JWT an execution client and its consensus client share.
- `Volume` (at `/persistent/<name>`; `unlock=` has no default) with `OperatorKey`, `TpmSeal` or `BrokerKey`; `Secret` as a systemd credential, bound by naming it in argv or `environment=`; `AttestedTLS` and `TLS`; `RootFS.verity()` and `RootFS.initramfs(max_size=)`; `Kernel(cmdline=)`; `Mkosi(settings=, scripts=)`, refusing what the compiler writes.
- **Breaking:** an image with a secret, an `AttestedTLS` ingress, firewall modes or a volume an operator unlocks runs the attested endpoint (`tundravm-endpoint.service`) instead of `secret-delivery`: its quote binds the nonce, its TLS key, the SSH host keys, the instance public key and each attested TLS certificate key, and it writes secrets, an operator-key volume's passphrase and the operator's SSH key only on the session that fetched that evidence, once per boot; `secrets.ready` waits for the required ones, and `sshd` waits only for its host keys.
- **Breaking:** an `OperatorKey()` volume has one owner: the first signed write pins the signer's SSH key in the volume's LUKS2 header and in an encrypted copy inside it, the endpoint then takes credentials, passphrases, mode switches and SSH keys only when signed by that key over the evidence's user data, a volume whose header and copy disagree is closed again, and the dev probe's `volume:` row names the owner (`owner SHA256:...`); so a reboot no longer hands root to whoever reaches the endpoint first. `TpmSeal` and `BrokerKey` volumes pin no one.
- **Breaking:** on TDX the attested endpoint takes a delivered SSH key, root's or a `Login`'s, only from an owner an `OperatorKey()` volume's encrypted copy confirmed this boot (unlock, then `attest` again), so an image without such a volume has no delivered root SSH on TDX; a simulated boot still takes the first.
- The certificate key of each `AttestedTLS` port is made at boot (`attested-tls-<port>-key.service`) and read by the relay as a credential; the dev probe's `attested-tls:` row reads each certificate back against the evidence, and an ingress relay starts only once its upstream's readiness holds.
- **Breaking:** `File(owner=)` and `Tree(owner=)` are applied at boot by the runtime-init step `owners`, which the services wait for, not by `/etc/tmpfiles.d/50-tundravm-owned.conf`, which nothing applied: the debloat masks boot-time tmpfiles.
- An initramfs-rooted image makes `/` `root:root 0755` before `sysinit.target` (`tundravm-root-mode.service`): the kernel's rootfs left it tmpfs's `1777`, writable by anyone and refused by sshd for every key under `/etc/ssh`; the dev probe's `root` row checks it on both root layouts.
- `SshAccess(login=Login(name, keys=, command= | shell=, sudo=[Sudo(...)], home=))` lets an account other than root in with its own keys (baked, or a `Secret` the attested endpoint writes to its `authorized_keys.d` file), into a forced command or a shell the image ships, with no password or forwarding and exactly the listed sudo rules (`/etc/sudoers.d/<name>`, `visudo -c` at build time); the dev probe's `login:` row reads each back, `ssh-login-shell` warns on a production shell without `command=`, and an image's own `SshAccess` now joins the control plane's instead of conflicting with it.
- `Container(name, argv, packages=, files=, state=, user=, expose=)` runs a program in a Debian root of its own: the subimage `mkosi.images/<name>/`, built from the image's snapshot and shipped in the measured payload as `/usr/lib/tundravm/containers/<name>.raw`, run under `RootImage=` with its own user and network namespace and a `systemd-socket-proxyd` forward per port; the manifest records each root's sha256 under `containers`, the probe's `container:<name>` row prints it, `container-shell` refuses a shell in production, and an OCI reference or a non-empty `egress=` is refused.
- **Breaking:** `Tdxs(issuer=)` is gone from `tundravm.components`: a development profile ships the `simulator` issuer beside the real one and takes it at boot where the execution gate finds no TDX, so a dev build attests `simulated` under QEMU; a production profile ships the real issuer only, and the declarative `Tdxs` refuses `simulator`.
- **Breaking:** `Network(egress=Egress(...))` drops every outbound packet but the baseline's NTS time and resolvers and what each component's `outbound()` names; `Service(egress=Egress(...))` accepts more for that service's user alone (nftables `meta skuid`); the cloud metadata servers (169.254.169.254, `fd20:ce::254`, Azure's wire server) take only tundravm's cloud glue and a service declaring `Egress(metadata=True)`, filtered image or not, so no other process fetches the identity token; `Egress(hosts=)` takes `HOST:PORT`, naming a metadata server there or an image-wide `metadata=True` is refused, and the boot probe's `egress:metadata:` rows send to it as each service's user.
- **Breaking:** a host name in `Egress(hosts=)` (`"logs.example:443"`) no longer opens its port to every address: the output chain accepts that port to the name's nftables sets alone (`host4_NAME`, `host6_NAME`, beside the modes' set in `inet filter`), which `egress-resolve` fills through `systemd-resolved` over DNS over TLS once the network is online and every 30s after (`egress-resolve.timer`), so a name is unreachable until it first resolves and keeps its last addresses while it does not; an address or a block is still a static rule. `TeeBase`'s NTS servers (TCP 4460), `Tdxs`' Intel hosts, `Observability`'s sinks and a service's own egress take the same path; The `Network`'s DNS-over-TLS resolvers stay literal (they resolve the rest), and NTP on UDP 123 goes to any address the NTS key exchange names, from chrony's user (`_chrony`) alone. The dev probe's `egress:HOST` rows print the addresses each name's sets hold.
- `Component.outbound()` says where a component sends, and a filtered image accepts it in each profile that holds it, each rule naming who asked: the shipped components cover their sinks and collateral, and `Observability(proxy=)` sends through one proxy.
- **Breaking:** `TeeBase` resolves through `systemd-resolved` over strict DNS over TLS (`DNSOverTLS=yes`, `DNSSEC=no` as flashbots-images, no fallback, LLMNR or mDNS) instead of a plain `/etc/resolv.conf`, so the host can neither read nor forge a lookup; `Network(dns=["ADDRESS#TLS-NAME"])` names the resolvers (Cloudflare's pair by default, `TeeBase(nameservers=)` is gone), the firewall accepts TCP 853 to them and no plain DNS, the GCP glue no longer points `/etc/resolv.conf` at the metadata server (`gcp-metadata-dns.service` is gone), and a development profile's boot probe gets a `dns` check.
- `Firewall(modes={"production": Mode(), "maintenance": Mode(ingress=[TCP(22)], lasts="30m")})` makes the firewall switchable: a port a mode names opens in that mode only, the image boots into `production`, `mode-switch` extends RTMR3 with each switch before it swaps the ruleset, old flows drop by `ct mark`, and a window closes itself on boot time; SSH in `production`, a mode named `tdx` or `simulated` and `lasts=` on `production` are refused. On TDX the extend needs Linux 6.16, so a 6.12 kernel refuses every switch.
- `Observability(proxy=Proxy(address, port, tls_name=))` reaches a proxy that speaks TLS at `https://<tls_name>:<port>`, the name mapped to the address in `/etc/hosts`.
- **Breaking:** `PrometheusRemoteWrite(export=)` is the keep-list of series that leave the TEE: series names and the `health` preset, dropped otherwise by `write_relabel_configs`; without it the agent keeps `health`, and `observability-export-unset` refuses a production profile that writes to a `url=`. Every keep-list carries the image's identity, `tundravm_image_digest` (the UKI's Authenticode SHA-384 RTMR1's event log records, and the image's name), `tundravm_image_rtmr` and `tundravm_mode`.
- `JournalExport()` and `PrometheusRemoteWrite()` without `url=` ship to a receiver in the guest (`journal-sink`, Debian's `systemd-journal-remote`; `metrics-sink`, Prometheus's remote-write receiver), both on the loopback, so a dev boot shows each export working; the credential binds once `url=` names the deployment's receiver, and a production profile reports `observability-sink-unset` until then.
- The GCP glue names NVMe disks as Google does, sets the hostname and routes forwarded IPs; the Azure glue installs the `curl` its ready report needs.
- **Breaking:** every image's UKI boots with `TeeBase`'s CPU mitigations, `mitigations=auto,nosmt spec_store_bypass_disable=on`, before what `Kernel(cmdline=)` appends; a parameter that turns a mitigation off (`nospectre_v2`, `mitigations=off`, `mds=off` and their kin) is refused, a repeat is `kernel-cmdline-repeated`, and a development profile's boot probe checks them in `/proc/cmdline` (`cmdline`).
- **Breaking:** `Kernel.build(base=DebianConfig("6.12.113-1"), fragments=[Path | KernelFragment(...)], patches=[Path | KernelPatch(...)], hardening=True, modules=False)` compiles, in the image, the stable release a Debian `linux-config` package carries, from gregkh/linux, and merges Tundra's hardening first by default (about 160 options, a reason each: io_uring, userfaultfd, kexec, KSM, `PROFILING`, `KALLSYMS_ALL`, `MPTCP`, `NETLABEL`, the `RD_*` decompressors but zstd and debug info off, lockdown, zeroed memory and stack canaries on); a fragment that sets an option itself wins, `hardening=False` is the `kernel-unhardened` error in a production profile and a warning in a development one, `config=Path(...)` is hardened too, and the build fails when a driver a target needs is not `=y` or a denied option is on, keeping its configs; the declarative `KernelHardening` is gone.
- `Component.kernel()` returns the `KernelFragment` and `KernelPatch` values a built kernel needs, merged after the kernel's own in declaration order; `RootFS.verity()` adds the dm-verity, erofs and overlay options, a `gcp` target the BadAML ACPI sandbox patch, and a component a `Profile` adds may ask for none, since every profile boots one kernel.
- **Breaking:** a relative host path in an image file (`File.copy(src, ...)`, `Tree(src, ...)`, `Kernel.build(config=, patches=)`, `AptRepository(key=Path(...))`) is beside the file that declares it, as `Local` is, not the working directory, so a build reads the same files from any directory.
- An image file imports modules from its own directory and its project's (the nearest `pyproject.toml`), from any working directory: a project carries its own components.
- `Mkosi(settings=)` writes each key in its mkosi section, and a key tundravm writes is refused with the public slot that sets it.
- **Breaking:** every error is one shape in the image file's words: what is wrong, naming the public object and keyword (`Service("app"): argv= is empty`), then a `fix:` line; `tundravm` prints it as one block with the image file's line and exits 2, as a crash or a usage error does, while a failed check exits 1; a misspelt keyword, a missing argument or a positional too many is a `ValidationError` with the closest keyword, and two services exposing one port and two services with one name are refused.
- `tundravm.testing`: `plan`, the asserts, `FakeMkosi`, `FakeSources`, `boot`, `assert_probe`, `run_cli`, and `FakeEndpoint`, which plays the endpoint, presenting each listener's certificate, with `relay`, `replay`, `wrong-key` and `wrong-certificate` misbehaviours.

- `deploy azure|gcp --build BUILD` never guesses the build; `upgrade` and `rollback` replace a GCP instance and move its volumes.

An Azure deploy records the address `az vm create` prints and adds no network security group rule (`--nsg-rule NONE`): the image's firewall decides what is open.

### Build and lock

- `build` publishes `build/<image>/production/<id>/` once, read-only, with a canonical `manifest.json` whose digest is `<id>`, `measurements.json` (a `tundravm.policy/2` policy per record), an SPDX SBOM, `observations.json` and a report of artifacts, sources, toolchains, phases and predicted registers.
- **Breaking:** the manifest is `tundravm.manifest/2`: `image_digest` replaces `recipe_digest`, in `show BUILD --json` and `lock --json` too; an older build directory is refused, so build again.
- **Breaking:** a production build needs `build/tundravm.lock` (`lock-missing`); a development build writes a missing one and re-pins `Local` sources.
- **Breaking:** lockfile version 8: profile sections are `profiles.<name>`, the payload and its digest `image` and `image_digest`, as the manifest says, and `toolchains` pins each Dotnet SDK; an older lock is refused, so run `tundravm lock` again.
- **Breaking:** the default Debian snapshot moves from `20251113T083151Z` to `20261018T082309Z`; `Debian(snapshot=)` keeps the old one.
- `lock` prints the snapshot, each source's ref and pin and the toolchain; `build --tree-only` without a lock says its tree will drift.
- `lock --check` never writes or fetches and exits 1 on drift; `build --reproduce`, `--sign`, `--offline` and `verify` check the bytes anywhere.
- A development build (`build --dev`, `dev`) is incremental: mkosi keeps the base tree after package install under `build/<image>/.work/.mkosi/incremental/`, with the Go and cargo caches, keyed on what its own cache manifest leaves out, and the next build of a changed file, unit or `Local` source reuses it and says so (`cached: packages (...)`); the manifest says `incremental`, and a production build never reads it.
- An initramfs disk's ESP is sized to hold `RootFS.initramfs(uki_max_size=)`, 256M by default (272 MiB); verity's stays 128 MiB, and a UKI past it fails naming `uki_max_size=`.
- `DebianConfig` reads the snapshot's main pool, then its security pool, which alone carries a kernel shipped as a security update.
- A kernel fixture with its own config builds in every driver a target needs; a weekly workflow builds it and Debian's newest 6.12 (6.12.113, from the security pool).
- A dev profile's root password (`DevAccess(password=)`, `DevTools`) is set inside the image with `mkosi-chroot chpasswd -e`, so the build no longer fails locking `/etc/passwd`; it logs in on the console only, unless `DevTools(network_login=True)` opens SSH to it.
- The version is the release tag (`tundravm --version`; `<tag>.post1.dev<n>+g<sha>` between tags), and a wheel records the commit it was built from, so an installed release builds `tools/` at its tag's commit; the lock's compiler section records that version, so another tundravm is lock drift.

### Sources and toolchains

- `Local("app")` sources are pinned by content digest (an edit is `local-changed`); `Git` and `Http` are fetched on the host, never in the sandbox.
- `GoBinary` builds the module root unless `package=` names a sub-command.
- `Build(command=[...])` runs one program in the build environment, beside `script=` and `using=`, and `Image(files=)` takes a `Build`, shipping what its `install=` names without a component.
- Go builds with the toolchain `go.mod` names, fetched by the host's `go` 1.21+, which every image needs (`Tdxs` is Go); Cargo with the one `rust-toolchain.toml` pins, installed by the host's `rustup`, and an unpinned channel is refused.
- **Breaking:** `Dotnet` builds with the SDK `global.json` names: `lock` resolves it under the file's `rollForward` policy against the .NET release manifest and pins the release with its tarball's sha512, `build` downloads it on the host and restores the packages with its own `dotnet`, and the sandbox restores and publishes offline with it; `packages=` defaults to the SDK's Debian runtime (`libicu76`, `libssl3t64`, `libstdc++6`), no SDK package, since Debian ships none, and `Dotnet`, `Go` and `Cargo` are `tundravm.sources` names.
- **Breaking:** a credential in a `Git` or `Http` url (`https://user:token@`, `?token=`) is refused, and the lock, the manifest and the SBOM are never written holding one; an SSH url still reads the agent.
- `Git(url, ref, auth="GITHUB_TOKEN")` and `Http(url, auth=...)` read the token from that host variable at lock, fetch and prefetch and hand it to git (`GIT_CONFIG_*`, reaching the git that Go, Cargo and `dotnet restore` run on the same host) or the download as a header, never to disk, the sandbox or an artifact; `auth=("VAR", "basic:USER")` or `("VAR", "bearer")` states the scheme where the variable alone guesses wrong (basic for github.com as `x-access-token` and `gitlab.*` as `oauth2`, bearer elsewhere): `("CI_JOB_TOKEN", "basic:gitlab-ci-token")` for a GitLab CI job token, `basic:x-access-token` for GitHub Enterprise.
- `Debian(repositories=[AptRepository(url, suite, key=)])` adds a signed archive, dated by the base's snapshot on snapshot.debian.org or pinned by `sha256=` of its `InRelease`, which `lock` records with its date, refusing an archive that moved, and the build checks (`build --offline` against the recorded digest); a key from `debian-archive-keyring` puts that package in the tools tree, and `convert --from mkosi` writes one for each signed, dated deb822 source of a `SandboxTrees=` tree.

### Tools

- **Breaking:** `Tdxs` and the volume and delivery tools build from `tools/` of this repository (`Git(url, sdk_commit, subdir="tools")`, or the checkout's `tools/` as a `Local`), not `Hyodar/tundra-tools` master; `Git(subdir=)` must name a directory of the commit.
- `tools/cmd/attested-endpoint` replaces `secret-delivery` and `tools/pkg/secrets`; `disk-setup owner` (`tundravm-volume-owner.service`) copies each owner token (`tundravm-owner`, LUKS2 token slot 2) to the endpoint before it starts and writes pins and rotations back, and `disk-setup` creates and opens an `OperatorKey()` volume only for the boot's owner, checking the copy in `/.tundravm/owner` (a volume made before this change gets it at its first unlock).
- **Breaking:** `tdxs` tags each quote with its caller, read from the socket's `SO_PEERCRED`: uid 0 is `endpoint`, any other uid its user name, so its `report_data` is `sha256(lp(tag) ‖ user data ‖ nonce)` and a `tdx`-group service can no longer quote an endpoint binding for its own TLS key; a non-root caller named or claiming `endpoint` and a uid without a user are refused, and `tools/pkg/verify` and `attested-client` refuse evidence from 8745 without the `endpoint` tag, so an image built before this change no longer attests.
- `tools/cmd/mode-switch`, a root daemon with no network, extends RTMR3 and loads each firewall mode in one `nft` transaction; the extend comes first, so a switch the quote does not show never happens.
- `tools/cmd/image-metrics` writes the image's identity series for the node exporter; `health` also keeps its `tundravm_system_state` and `tundravm_units_failed`.
- `tools/pkg/verify` (one function, `AttestedTLS`) and `go run ./cmd/attested-client https://HOST:PORT` give a relying party the `attest --tls` check and verdicts in Go, a TDX quote's chain checked against Intel's root.
- `key-gen` draws random keys from `crypto/rand` only, never the host's `/dev/hwrng`; `disk-setup` closes a volume that fails to mount or to read its owner copy; `tdxs` hangs up on a malformed request instead of spinning.
- The unit suite runs on every core: `pytest-xdist` is a dev dependency and `pytest -m "not integration"` spreads over `-n auto`; a run that may select the integration tests stays serial.
